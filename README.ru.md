Announce задается в панели Remnawave или в конфигурации прокси:

```
Использовано {TRAFFIC_USED} из {TRAFFIC_LIMIT} · осталось {DAYS_LEFT} дн.
```

Клиент получает его с подставленными значениями:

```
Использовано 10.50 GB из 100.00 GB · осталось 12 дн.
```

## Возможности

- **Шаблонные переменные** - Подставляет `{TRAFFIC_USED}`, `{TRAFFIC_AVAILABLE}`, `{DAYS_LEFT}` и другие в параметры
  подписки
- **Плейсхолдеры без запросов** - Трафик и срок берутся из заголовков ответа, поэтому обычный случай не требует
  обращений к API; имя, статус и суммарный трафик приходят из панели, с кэшем и склейкой одинаковых запросов
- **Два источника шаблонов** - Announce можно писать в Custom Response Headers панели или в `config.yaml`
- **Условные правила** - Разный текст для разных типов клиентов, user-agent или статусов
- **Резервный кэш** - Опционально отдает последнюю удачную подписку, пока Remnawave недоступен
- **Принудительный безлимит** - Опционально показывает безлимит независимо от квоты в панели
- **Перемешивание хостов** - Опционально перемешивает серверы, подходящие под шаблон имени, чтобы пользователи
  распределялись между ними
- **Прозрачное проксирование** - Регистр заголовков, цепочка `X-Forwarded-*` и обрыв соединения при ошибке сохраняются
- **Готов к Docker** - Мультиарх-образ, non-root, только чтение, самопроверка healthcheck

## Требования

Docker и Docker Compose, панель Remnawave с настроенной страницей подписки и
API-токен из Remnawave Settings → API Tokens. Сама страница подписки идет в
compose-файле, если еще не запущена.

## Как это работает

Прокси встает перед официальной
[страницей подписки](https://github.com/remnawave/subscription-page) и переписывает
заголовки ответа. Сама страница не меняется: веб-интерфейс, определение браузера,
шаблоны под разные клиенты, legacy-ссылки Marzban и subpage-конфигурации
продолжают работать, обновления апстрима остаются применимыми.

```
клиент → caddy/nginx :443 → subpage-proxy :3020 → subscription-page :3010 → панель
                                  │
                                  └── GET /api/sub/{shortUuid}/info   (только если понадобится)
```

Данные о трафике и сроке действия берутся из заголовка `subscription-userinfo`,
сопровождающего каждый ответ подписки, поэтому в обычном случае **запросов к API
не требуется**. Обращение к панели происходит только за данными, которых нет в
заголовках, — например `{USERNAME}` или `{USER_STATUS}`; такие запросы
кэшируются, а одновременные одинаковые объединяются в один.

## Быстрый старт

```bash
git clone https://github.com/hteppl/remnawave-subpage-proxy.git
cd remnawave-subpage-proxy

cp .env.example .env
cp .env.subscription-page.example .env.subscription-page
cp config.example.yaml config.yaml

# Впишите REMNAWAVE_API_TOKEN в оба .env-файла.
# Токен создается в Remnawave Dashboard → Remnawave Settings → API Tokens.

docker compose pull
docker compose up -d
```

`config.yaml` необязателен: без него прокси заполняет плейсхолдеры, заданные в
Custom Response Headers панели.

Для сборки из исходников вместо готового образа служит `make dev`: он применяет
`docker-compose.dev.yml`, который собирает тег `:dev` локально, переводит логи в
`debug`/`text` и публикует health-порт на 3021.

Далее обратный прокси направляется на прокси вместо страницы подписки. Порты на
хост не публикуются: контейнеры доступны только внутри `remnawave-network`,
поэтому обратный прокси, подключенный к этой сети, обращается к ним по имени.

```caddy
sub.example.com {
    reverse_proxy remnawave-subpage-proxy:3020
}
```

Если обратный прокси работает на хосте, а не в Docker, порт нужно опубликовать,
добавив сервису в compose-файле `ports: ['127.0.0.1:3020:3020']`.

### Развернутая страница подписки

Используется `docker-compose.proxy-only.yml`; из compose-файла страницы следует
убрать проброс `ports:`, чтобы она была доступна только через прокси.

```bash
cp .env.example .env
cp config.example.yaml config.yaml
docker compose -f docker-compose.proxy-only.yml up -d
```

## Заметки для продакшена

Вместо отслеживания `latest` рекомендуется фиксировать конкретную версию. Оба
compose-файла запускают контейнер только для чтения, со снятыми capabilities,
установленным `no-new-privileges` и ограничением JSON-лога до 3 × 10 МБ.

`LOG_FORMAT=json` рекомендуется, если логи передаются во внешнюю систему.
`HTTP_SHUTDOWN_TIMEOUT` должен быть меньше `stop_grace_period` из compose (по
умолчанию 15s и 20s), чтобы текущие запросы успевали завершиться до остановки.

Панель проверяется однократно при старте; неудача фиксируется в логе на уровне
error, но не препятствует работе.

## Настройка announce

Шаблон может задаваться в любом из двух мест; оба применяются.

**В панели** — Remnawave Settings → Subscription Settings → Custom
Response Headers:

| Заголовок  | Значение                                         |
|------------|--------------------------------------------------|
| `announce` | `Использовано {TRAFFIC_USED} из {TRAFFIC_LIMIT}` |

Прокси подставляет значения в исходящем ответе; больше ничего не требуется.
`scan_all_headers` включен по умолчанию, поэтому механизм действует для любого
заголовка панели, а значения в base64 декодируются, заполняются и кодируются
обратно на месте.

**В `config.yaml`** — для шаблонов в системе контроля версий либо с условиями:

```yaml
vars:
  BRAND: "MyProject"
  SUPPORT: "@my_support_bot"

headers:
  - name: announce
    template: "{BRAND} · израсходовано {TRAFFIC_USED} из {TRAFFIC_LIMIT} · осталось {DAYS_LEFT} дн. · {SUPPORT}"
    encode: base64-prefixed   # требуется для Happ
    max_length: 200           # Happ показывает максимум 200 символов

  # Альтернативный текст при исчерпании лимита.
  - name: profile-title
    template: "{BRAND} — {TRAFFIC_AVAILABLE}"
    encode: base64
    max_length: 25
```

Все доступные параметры описаны в [`config.example.yaml`](config.example.yaml),
а в [`examples/`](examples/) лежат готовые конфигурации под типовые сценарии.

## Плейсхолдеры

Синтаксис — `{NAME}`. Модификаторы необязательны и объединяются в цепочку:
`{NAME|upper}`, `{NAME|lower}`, `{NAME|trim}`, `{NAME|truncate:40}`,
`{NAME|default:n/a}`. Имена записываются в `UPPER_SNAKE_CASE`, поэтому JSON- и
Clash-конфигурации, проходящие через прокси, не считаются шаблонами.

### Разрешаются без запроса к панели

| Плейсхолдер                 | Пример                                        |
|-----------------------------|-----------------------------------------------|
| `{TRAFFIC_USED}`            | `10.50 GB`                                    |
| `{TRAFFIC_LIMIT}`           | `100.00 GB`                                   |
| `{TRAFFIC_AVAILABLE}`       | `89.50 GB` (лимит минус израсходованное)      |
| `{TRAFFIC_USED_BYTES}`      | `10500000000`                                 |
| `{TRAFFIC_LIMIT_BYTES}`     | `100000000000`                                |
| `{TRAFFIC_USED_IN_LIMIT}`   | `3.0` (расход в единице лимита, без суффикса) |
| `{TRAFFIC_LIMIT_VALUE}`     | `20.0` (лимит без суффикса)                   |
| `{TRAFFIC_UNIT}`            | `GB` (общая единица)                          |
| `{TRAFFIC_AVAILABLE_BYTES}` | `89500000000`                                 |
| `{TRAFFIC_UPLOAD}`          | `0.50 GB`                                     |
| `{TRAFFIC_DOWNLOAD}`        | `10.00 GB`                                    |
| `{TRAFFIC_USED_PERCENT}`    | `10`                                          |
| `{TRAFFIC_LEFT_PERCENT}`    | `90`                                          |
| `{PROGRESS_BAR}`            | `▰▱▱▱▱▱▱▱▱▱`                                  |
| `{DAYS_LEFT}`               | `12`                                          |
| `{EXPIRES_AT}`              | `31.12.2026 23:59`                            |
| `{EXPIRES_AT_DATE}`         | `31.12.2026`                                  |
| `{EXPIRES_AT_TIME}`         | `23:59`                                       |
| `{EXPIRES_AT_UNIX}`         | `1798761599`                                  |
| `{SHORT_UUID}`              | `aBcDeF123`                                   |
| `{CLIENT_TYPE}`             | `clash`                                       |
| `{USER_AGENT}`              | `Happ/1.0`                                    |
| `{CLIENT_IP}`               | `203.0.113.9`                                 |
| `{ORIGINAL_VALUE}`          | текст самого заголовка до перезаписи          |
| `{NOW}` `{DATE}` `{TIME}`   | `01.09.2026 14:30`                            |
| `{SUBSCRIPTION_URL}`        | `https://example.com/sub/aBcDeF123`           |

`{TRAFFIC_USED_IN_LIMIT}`, `{TRAFFIC_LIMIT_VALUE}` и `{TRAFFIC_UNIT}` выводят обе
части квоты в одной единице: `{TRAFFIC_USED_IN_LIMIT} из {TRAFFIC_LIMIT}` дает
`0.0 из 20.0 GB` там, где `{TRAFFIC_USED}` дал бы `0 B из 20.0 GB`. Единица
берется от лимита.

`{ORIGINAL_VALUE}` содержит текст, который панель прислала для заголовка правила,
декодированный, если он был в base64, — так `template` может обернуть announce из
панели, а не отбросить его; плейсхолдеры панели внутри тоже раскрываются.

`{SUBSCRIPTION_URL}` формируется из самого запроса и не требует обращения к
панели; сегмент с типом клиента отбрасывается, из `/{shortUuid}/clash`
получается ссылка `/{shortUuid}`.

На безлимитном тарифе `{TRAFFIC_LIMIT}` и `{TRAFFIC_AVAILABLE}` отображаются как
`∞` (текст настраивается), как и `{EXPIRES_AT}` у бессрочной подписки.

### Требуют запроса к панели (результат кэшируется)

| Плейсхолдер                | Пример                                          |
|----------------------------|-------------------------------------------------|
| `{USERNAME}`               | `alice`                                         |
| `{USER_STATUS}`            | `ACTIVE` `DISABLED` `LIMITED` `EXPIRED`         |
| `{IS_ACTIVE}`              | `true`                                          |
| `{TRAFFIC_LIMIT_STRATEGY}` | `NO_RESET` `DAY` `WEEK` `MONTH` `MONTH_ROLLING` |
| `{LIFETIME_TRAFFIC_USED}`  | `1.20 TB`                                       |

Дополнительно — любые переменные, заданные в разделе `vars:` файла `config.yaml`.

## Условия

Правила можно ограничивать, чтобы разные клиенты или пользователи получали
разный текст:

```yaml
headers:
  # Только Happ.
  - name: announce
    template: "{PROGRESS_BAR} израсходовано {TRAFFIC_USED_PERCENT}%"
    encode: base64-prefixed
    when:
      user_agent: "(?i)happ"

  # Только пути /json и /clash; `user_statuses` задается так же.
  - name: X-Plan-Summary
    template: "{TRAFFIC_USED} / {TRAFFIC_LIMIT}"
    when:
      client_types: [ json, clash ]

  # Тарифы с квотой; `false` — безлимитные.
  - name: announce
    template: "израсходовано {TRAFFIC_USED} из {TRAFFIC_LIMIT}"
    encode: base64-prefixed
    when:
      has_traffic_limit: true

  # Значение по умолчанию, применяется только если панель не прислала заголовок.
  - name: support-url
    template: "https://t.me/my_support_bot"
    when:
      exists: false
```

`has_traffic_limit` отличает ограниченную квоту от безлимитного тарифа, который
Remnawave кодирует нулевым total. Значение читается из заголовка
`subscription-userinfo`, поэтому обычно не требует запроса к панели; правило
пропускается, если квоту определить не удалось.

`traffic.force_unlimited` на это условие не влияет: он меняет то, что видит
клиент, тогда как `has_traffic_limit` проверяет квоту, заданную в панели, — тариф
с лимитом можно показывать безлимитным, и он все равно будет соответствовать
условию `has_traffic_limit: true`. `user_statuses` всегда вызывает запрос к панели,
поскольку статуса нет в заголовках ответа.

## Справочник конфигурации

Инфраструктура настраивается переменными окружения, шаблонизация — через
`config.yaml`. Значения ниже действуют, если переменная не задана;
[`.env.example`](.env.example) переопределяет часть из них.

| Переменная                            | По умолчанию  | Назначение                                                           |
|---------------------------------------|---------------|----------------------------------------------------------------------|
| `UPSTREAM_URL`                        | —             | Проксируемая страница подписки. **Обязательна.**                     |
| `REMNAWAVE_PANEL_URL`                 | —             | Адрес панели. Обязателен, если `PANEL_ENABLED` не выключен.          |
| `REMNAWAVE_API_TOKEN`                 | —             | API-токен панели. Обязателен, если `PANEL_ENABLED` не выключен.      |
| `APP_HOST`                            | `0.0.0.0`     | Публичный адрес прослушивания.                                       |
| `APP_PORT`                            | `3020`        | Публичный порт.                                                      |
| `HEALTH_HOST`                         | `0.0.0.0`     | Адрес для health-эндпоинтов.                                         |
| `HEALTH_PORT`                         | `3021`        | Порт health-эндпоинтов. `0` — выключить оба.                         |

| `CLOUDFLARE_ZERO_TRUST_CLIENT_SECRET` | —             | `CF-Access-Client-Secret` для того же случая.                        |
| `SUBSCRIPTION_CACHE_ENABLED`          | `false`       | Отдавать последний удачный ответ, пока Remnawave недоступен.         |
| `SUBSCRIPTION_CACHE_TTL`              | `1h`          | Сколько сохраненный ответ остается пригодным.                        |
| `SUBSCRIPTION_CACHE_MAX_BYTES`        | `64MiB`       | Общий бюджет памяти под резервный кэш.                               |
| `SUBSCRIPTION_CACHE_MAX_BODY`         | `1MiB`        | Максимальный размер одного сохраняемого ответа.                      |
| `UPSTREAM_TIMEOUT`                    | `60s`         | Ожидание заголовков ответа от апстрима.                              |
| `HTTP_READ_TIMEOUT`                   | `30s`         | Чтение запроса клиента.                                              |
| `HTTP_WRITE_TIMEOUT`                  | `90s`         | Запись ответа.                                                       |
| `HTTP_IDLE_TIMEOUT`                   | `120s`        | Простой keep-alive соединения.                                       |
| `HTTP_SHUTDOWN_TIMEOUT`               | `15s`         | Завершение по SIGTERM. Должен быть меньше `stop_grace_period`.       |

`CACHE_TTL=45` и `CACHE_TTL=45s` эквивалентны. Размер принимает `1MiB`, `512KB` или
число без суффикса.

### Принудительный безлимит

`traffic.force_unlimited` скрывает квоту из встроенного индикатора трафика,
независимо от того, что задано в панели:

```yaml
traffic:
  force_unlimited: true
```

Заголовок `subscription-userinfo` передается со значением `total=0` — стандартной
кодировкой безлимитного тарифа, которую клиентские приложения читают для показа
остатка. Переписывается только этот заголовок: плейсхолдеры и условия продолжают
сообщать реальную квоту, поэтому `{TRAFFIC_LIMIT}` по-прежнему даст `100.00 GB`,
а `has_traffic_limit: true` сработает. Опция управляет единственным, на что
шаблон повлиять не может, — индикатором трафика в приложении.

### Резервный кэш подписок

По умолчанию отключен, включается параметром `SUBSCRIPTION_CACHE_ENABLED=true`.
Прокси сохраняет последний успешный ответ подписки для каждого клиента и отдает
его, пока Remnawave недоступен, — у существующих пользователей сохраняется
рабочая конфигурация на время аварии панели или перезапуска страницы.

Это резервный, а не сквозной кэш: каждый запрос сначала идет в апстрим, и
сохраненная копия используется только при его неудаче — обрыве соединения,
таймауте или ответе 5xx. Записи различаются по короткому UUID, типу клиента,
`User-Agent` и `Accept-Encoding`, поскольку Remnawave формирует разную нагрузку
для разных клиентов; кэшируются только подписки, но не веб-страница.

Два следствия: счетчики трафика в таком ответе соответствуют возрасту записи, а
пользователь, отключенный во время аварии, сохраняет доступ до истечения
`SUBSCRIPTION_CACHE_TTL`.

### Перемешивание хостов

Клиенты обычно подключаются к первому хосту в подписке, поэтому при фиксированном
порядке все пользователи попадают на один сервер. `hosts.shuffle` задает группы хостов
регулярными выражениями Go, которые сопоставляются с видимым клиенту именем —
фрагмент ссылки или `ps` у vmess, `remarks` у Xray, `tag` у sing-box, `name`
прокси у Clash. При каждом запросе хосты группы перемешиваются между позициями,
которые уже занимают, а хост, не подошедший ни под один шаблон, остается на
месте:

```yaml
hosts:
  shuffle:
    - "(?i)premium"    # все Premium-узлы меняются местами
    - "^🇩🇪 "           # вторая, независимая группа
```

Адреса серверов не проверяются, поэтому перегруппировать хосты можно
переименованием в панели. Хост, подходящий под несколько групп, относится к
первой, `".*"` перемешивает все, а по умолчанию список пуст — пока группа не
задана, тело ответа не буферизуется и не переписывается.

Формат определяется по содержимому, независимо от пути и user-agent. Список ссылок, в base64 или нет, перемешивается
построчно; `/json` и
`/v2ray-json` переставляют целые конфиги Xray; в sing-box перемешиваются
outbound-ы узлов, а каждый selector или urltest, перечисляющий их по тегу,
следует за ними; в YAML для Clash, Mihomo и Stash перемешивается список
`proxies`, а за ним proxy-группы. `DIRECT`, `REJECT` и имена групп остаются на
местах, веб-страница не затрагивается.

При включенном перемешивании прокси запрашивает у апстрима несжатое тело на
путях подписки; тело, пришедшее сжатым, или больше 8 МиБ, передается без
изменений. Ответ из резервного кэша тоже перемешивается.

### Блокировка сканеров

Автоматические переборы `/.env`, `/.git/HEAD`, `/config/.env` и подобных
отклоняются прокси и не доходят ни до страницы подписки, ни до панели. В ответ
возвращается пустой `404`, в лог — запись на уровне `debug`:

```yaml
block:
  enabled: true
  patterns:
    - "(?i)/telescope"
```

`enabled: false` выключает фильтр целиком, вместе с собственными `patterns`.

Встроенно отклоняются: любой сегмент пути, начинающийся с точки; типы файлов,
которые запрашивают сканеры (`.php`, `.sql`, `.bak`, `.ini`, `.key` и подобные),
в любом сегменте — завершающий слэш проверку не обходит; и первые
сегменты вроде `env`, `wp-admin` или `phpmyadmin`, которые оцениваются уже
после снятия `CUSTOM_SUB_PREFIX`. `..` отклоняется везде, в том числе внутри
`/assets`.

Исключений всего два: `.well-known` с ACME-челленджами и `security.txt` — в
любом регистре — и собственный файл страницы `/assets/.app-config-v2.json`.
Короткие UUID панель выдает как nanoid, поэтому на практике встроенные имена с
реальной подпиской не пересекаются, но форма нигде не проверяется.

### Проверки состояния

`/healthz` на `HEALTH_PORT` отвечает за liveness, `/readyz` дополнительно
проверяет доступность апстрима. Оба вынесены на отдельный порт, чтобы ни один
путь не мог перекрыть короткий UUID, а `HEALTHCHECK` контейнера обращается к
эндпоинту тем же бинарником — образу не нужны ни шелл, ни `curl`.

## Особенности поведения

- **Регистр заголовков сохраняется.** Разбирая ответ, Go приводит имена
  заголовков к каноническому виду (`announce` → `Announce`); прокси возвращает
  написание, в котором их отдает страница подписки, — клиенты получают то же, что
  и до внедрения прокси.
- **Обработка base64 безопасна.** Значение декодируется и кодируется обратно
  только если внутри обнаружен плейсхолдер; все остальное передается байт в байт.
- **`X-Forwarded-*` дополняется, а не перезатирается,** поэтому страница подписки
  определяет настоящего клиента своим же `TRUST_PROXY=1`. Запросы, которые
  апстрим не принимает, обрываются, а не обслуживаются, — как делает и сама
  страница.
- **Панель не находится на критическом пути.** При ее недоступности подписки
  продолжают отдаваться, а зависимые от нее плейсхолдеры сохраняют исходный текст.
- **Legacy-ссылки Marzban работают частично.** В сегменте пути у них непрозрачный
  токен, а не короткий UUID, поэтому пользователь не определяется: трафик и срок
  подставляются из заголовка ответа, `{USERNAME}` и другие данные из панели — нет.
